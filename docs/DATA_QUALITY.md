# 五笔 86 知识数据质量规范

## 1. 目的

五笔学习产品的核心资产不是界面，而是准确、可解释、可追溯的知识数据。错误的字根、编码或拆字示例会直接误导学习者，因此数据准确性必须作为发布门槛。

本规范适用于字根表、键位映射、助记、键名字根、成字字根、汉字拆分、简码、全码、末笔字型识别码和练习题。

## 2. 版本边界

- 产品当前只支持 **五笔 86 版**。
- 每条正式知识记录必须明确版本为 `86`。
- 不得将 98 版、新世纪版或其他变体的数据混入 86 版数据集。
- 若资料对版本标注不清，记录为待核验，不得默认归入 86 版。

## 3. 来源要求

每条正式知识数据必须记录来源。建议来源元数据包含：

- sourceId：稳定来源标识
- title：资料名称
- authorOrPublisher：作者或发布方
- edition：版次/版本信息
- urlOrReference：URL 或可定位的书籍/文档信息
- accessedAt：访问或核验日期（适用时）
- notes：适用范围、差异和核验说明

应优先使用可信、版本明确、可复核的资料。注意资料许可和版权：只记录产品所需的事实性数据与必要引用，不复制受版权保护的大段教材内容。

## 4. 严禁事项

AI Agent 和开发者不得：

- 凭模型记忆生成完整字根表。
- 根据字形直觉推断汉字编码。
- 根据一个相似汉字类推其他汉字的拆分。
- 将拼音输入规则、其他五笔版本规则混入 86 版。
- 混淆键名字根、成字字根、一级简码、二级/三级简码和四码全码。
- 把简码当作完整编码，或把全码误标成简码。
- 将未核验的示例写入正式课程、练习或生产数据。
- 在来源冲突时自行选择一个看起来合理的答案而不记录冲突。

可以使用临时 mock 数据构建 UI，但必须显式标记为 mock，并确保不会被生产数据加载。

## 5. 数据分类

建议分别管理以下数据：

1. **键位与字根**：键位、字根形态、所属区、助记、例字。
2. **特殊字根类别**：键名字根、成字字根及其专属输入规则。
3. **汉字拆分**：字根序列、拆分顺序、规则说明。
4. **编码记录**：编码字符串、编码类型、取码过程。
5. **课程内容**：讲解、示例、练习与知识点引用。

课程和练习应引用知识数据 ID，而不是重复维护同一份字根或编码事实。

## 6. 编码与拆字的表达

必须显式区分：

- 键名字根
- 成字字根
- 一级简码
- 二级/三级简码
- 四码全码（以及适用规则下的其他编码情形）

对汉字的教学记录应尽可能保留：
- 适用版本
- 编码类型
- 编码序列
- 拆分得到的字根序列
- 末笔字型识别码等必要信息
- 规则解释
- 来源和核验状态

不能假设每个汉字都只有一种编码记录，也不能假设每种编码都可以用同一条简单的“取前几个字根”规则解释。

## 7. 核验流程

推荐状态：

- `draft`：录入草稿，尚未核验。
- `needs_review`：来源不足或存在疑问。
- `verified`：已完成来源核对与规则复核。
- `rejected`：确认错误或不适用于本产品版本。

正式课程和生产练习只能引用 `verified` 数据。

每条记录的核验至少检查：

1. 版本是否为 86。
2. 来源是否明确且可复查。
3. 键位、字根或编码是否与来源一致。
4. 编码类型是否标注正确。
5. 拆字顺序和取码解释是否一致。
6. 是否存在来源冲突或特殊情况。
7. 自动校验和人工复核是否完成。

## 8. 自动化校验

建议建立数据校验脚本，至少检查：

- ID 唯一。
- 所有引用的 rootId、sourceId、exerciseId 存在。
- 字根键位符合允许的键位集合。
- 编码字符符合产品定义的键位范围。
- 编码长度与对应编码类型的规则一致（特殊类型单独处理）。
- 课程引用的练习存在。
- 正式课程引用的数据均为 verified。
- 版本字段统一为 86。
- 同一记录不存在未经解释的重复或冲突。
- 拆字序列与编码记录之间满足已实现且经过测试的规则。

自动校验只能发现结构性和规则性问题，不能替代人工核验来源和教学解释。

## 9. 变更管理

- 数据修改应像代码一样走审查。
- 重要变更记录来源、修改原因和核验人/核验日期。
- 规则或来源变化时增加回归测试。
- 不要在组件中硬编码字根或编码。
- 发现数据错误时，应检查相关课程、练习、错题和统计是否受影响。

## 10. 发布门槛

以下任一条件不满足，不得把对应数据发布为正式教学内容：

- 无法确认适用 86 版。
- 没有可追溯来源。
- 编码类型不明确。
- 拆分或取码过程无法解释。
- 自动校验失败。
- 来源之间存在未解决的冲突。

**默认策略：不确定就不教；先标记待核验，不要猜。**
